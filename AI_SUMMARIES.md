# AI Meeting Summaries

Resident-facing AI summaries for each meeting, plus clickable agenda links on the
index page. Summaries are generated by `riverhead_summarize.py` (Claude API),
stored inside each transcript JSON, and rendered at the top of the meeting page.

## What changed

- **`riverhead_summarize.py`** (new): generates a summary per transcript and writes
  it into the JSON under a `summary` key. Idempotent: only meetings without a
  current summary are processed, so re-runs resume and the nightly job is cheap.
- **`riverhead_build_site.py`**: renders the stored summary at the top of each
  meeting page (open by default, collapsible) and turns the index "Agenda" badge
  into a real link to the agenda PDF.
- **`run_pipeline.sh`**: new Step 3b runs the summarizer before the build. It is
  non-fatal, so a missing key or API hiccup never blocks publishing.
- **`.gitignore`**: ignores `riverhead.env` (the key) and `agenda_cache/`.

## One-time setup (on the Mac that runs the pipeline)

**1. Install dependencies**

```
pip3 install anthropic
# if your Python is externally managed, instead use:
# pip3 install --break-system-packages anthropic
```

**2. Create the API key file.** This holds your Anthropic key and is gitignored.
Do this yourself so the key never passes through anything else:

```
printf 'ANTHROPIC_API_KEY=%s\n' 'sk-ant-YOURKEYHERE' > ~/Projects/riverhead-transcripts/riverhead.env
chmod 600 ~/Projects/riverhead-transcripts/riverhead.env
```

The nightly launchd job reads this file automatically (launchd has no shell
profile, so the key must live here, not in `~/.zshrc`).

## Backfill the existing 280 meetings

Do a small test first, eyeball the output, then run the full backfill.

```
cd ~/Projects/riverhead-transcripts

# The script reads the key straight from riverhead.env (no need to source it).
# Test on 2 meetings, then preview locally:
python3 riverhead_summarize.py --limit 2
./build.sh
cd docs && python3 -m http.server 8000   # open a couple meeting pages, Ctrl-C when done
cd ..

# Happy with it? Run the whole backfill (skips 7 too-short meetings):
python3 riverhead_summarize.py
```

Expected: about 273 summaries generated, 7 skipped as too short. Roughly 15 to 30
minutes at 4 workers.

## Troubleshooting

**401 invalid x-api-key.** The script reads the key from `riverhead.env` (the file
wins over any stale `ANTHROPIC_API_KEY` left in your shell) and preflights one call,
so a bad key fails once with a clear message instead of on every meeting. If you hit
it:

- Confirm `riverhead.env` holds a current key from console.anthropic.com. A key
  looks like `sk-ant-api03-...` and is about 108 characters.
- Inspect the file key's shape without revealing it:
  `python3 -c "v=[l.split('=',1)[1].strip().strip(chr(34)).strip(chr(39)) for l in open('riverhead.env') if l.startswith('ANTHROPIC_API_KEY=')][0];print('len',len(v),'prefix',v[:12])"`
- The startup line `key source: riverhead.env (length N, starts sk-ant-...)` shows
  which key is actually in use.

**Agenda grounding is currently OFF.** The portal URL's agenda id is a different id
space than the API's file-stream id, so grounding on it would risk attaching the wrong
agenda (it returned a 2007 document for a 2026 meeting in testing). It is disabled via
`GROUND_IN_AGENDA = False` in `riverhead_summarize.py`; summaries generate from the
transcript alone, which tested accurate. Re-enabling is a follow-up once the correct
file-id lookup is wired, with a date check so any mismatched agenda is discarded.

## Going forward

The nightly pipeline (Step 3b) summarizes any new meeting before building, so new
transcripts publish with a summary automatically. No action needed as long as
`riverhead.env` exists.

## Cost

At current pricing, the full backfill is roughly $12 to $16 on Sonnet 4.6, and a
few cents per meeting after that (a handful of dollars per year). Switch to a
cheaper model with `--model claude-haiku-4-5-20251001` or by setting `ANTHROPIC_MODEL`.

## Tuning

- **Length:** `length_tier()` in `riverhead_summarize.py` sets the word target per
  meeting size. The page hard-caps nothing; the model is instructed to stay under
  the target.
- **Voice and rules:** the `SYSTEM` prompt in the same file. It forbids inventing
  names, numbers, and votes, and tells the model to trust the agenda over the
  garbled transcript for spellings.
- **Regenerate everything** after a prompt change: bump `PROMPT_VERSION`, then
  `python3 riverhead_summarize.py --force`.
- **Look of the block:** `.transcript-summary` styles in the `CSS` string in
  `riverhead_build_site.py`.

## Notes

- Summaries are excluded from the Pagefind search index (`data-pagefind-ignore`),
  so search stays grounded in the actual transcript.
- Each summary page carries a visible disclaimer that it is auto-generated from an
  unofficial transcript. These are characterizations of real officials on a public
  site, so spot-check a sample before and after the first backfill.
